# g6ct on Windows - the same MatrixEncoder as a VST2 insert

The DSP here is not a reimplementation of a reimplementation: `upstream/g6ct.c`
is the C11 file from [`../port/`](../port/), unchanged and still bit-exact to
`KSUSBAPO64.dll`'s `CMatrixEncoderEfxMod`. What this directory adds is the
**Windows delivery** of that node, in two forms:

| form | when you need it | files |
|---|---|---|
| **VST2 insert plugin** | the endpoint is 2.0 (or a virtual 7.1 device carries the stream), so a user-space host has to run the fold | `plugin/`, `tools/vst_nulltest.py` |
| **EqualizerAPO config** | the endpoint is a real 8-channel device and audiodg can run an SFX APO | `out/g6ct.txt`, generated by `tools/mkconfig.py` |

Full write-up, evidence trail and the VoiceMeeter/Element wiring:
[`WINDOWS.md`](WINDOWS.md).

## Why a plugin at all

On the G6 the 7.1 to 2 downmix happens in a host APO, before the device. On a
Logitech G733 with the modded INF the physical endpoint is **2.0**, so there is
no 8-channel endpoint left for an APO to sit on - and VoiceMeeter's VAIO
endpoints expose no APO slots at all (their `FxProperties` has zero values).
The fold therefore has to happen in user space:

```
app --7.1--> Voicemeeter Input (VAIO, 8ch/48k, mask 0x63F)
             |
             v  strip -> Insert Virtual ASIO, IN#4 (ASIO channels 6..13)
          Element -- g6ct.dll --> binaural L/R
             |
             v  bus A1, exclusive WDM
          G733 @ 2ch/48k/16-bit
```

Element is the host because it can patch a single stereo output pair back onto
the insert bus. The plugin is 8 in / 2 out on purpose: with only two output
ports there is no third port for a stale surround channel to survive on, so the
round-trip doubling that an 8-out insert has to defend against cannot happen.

## Quick start

```powershell
# 1. build the plugin (mingw64 gcc, no MSVC, no Windows SDK)
powershell -NoProfile -ExecutionPolicy Bypass -File plugin\build.ps1

# 2. prove it is still bit-exact before trusting it
python tools\vst_nulltest.py --double
#   ... PASS
```

Then point the host's VST2 scan path at `plugin\`, drop the plugin into the
graph, wire IN#4 1-8 into it and its L/R out to the bus pair. Element caches
plugin metadata in `%APPDATA%\Kushview\Element\plugins.xml`, so delete and
re-add the node whenever the channel count changes.

## Verification

Everything below is reproducible from this directory with the four stimulus
files in `work/` (see [`work/README.md`](work/README.md)).

| what | result | log |
|---|---|---|
| `test_ir_f64` - IR matrix, all-pass shape, pole stability | `0x5f78798536b3fa72`, `PASSED (0 failures)` | `verification_test_ir_f64.txt` |
| `test_ir_f32` | `0x684d7c9b2515f759`, `PASSED (0 failures)` | `verification_test_ir_f32.txt` |
| plugin vs `g6ct_cli_f64` render | peak **0.000e+00**, sha `08e56173fa90ac5d` = ref | `verification_vst_nulltest.txt` |
| f64 host path | 5.96e-08, -152.01 dB (the reference's own f32 rounding) | same |
| block sizes 37..144000 | identical hash, zero residual at every size | same |
| cppcheck 2.19 + gcc `-fanalyzer` | no findings in the DSP, one ABI-only note in the wrapper | `verification_cppcheck.txt` |

`processReplacing` is bit-exact, not "close": the float32 host buffers are
widened per sample, the DSP accumulates in `double`, and the narrowing back is
exact because the reference is itself a float32 render.

## Requirements

- mingw64 gcc (`choco install mingw`) - the build script looks in
  `C:\ProgramData\mingw64\mingw64\bin` first, then `PATH`.
- Python 3.10+ with `numpy` for the test harnesses; `pyaudiowpatch` and
  `pycaw` only for the live/loopback probes.
- Optional: `choco install cppcheck` to reproduce the static-analysis log.

## What is NOT in here

- No Creative binaries and no decompiled Sound Blaster Command code (same
  policy as the rest of this repo). The DSP was reverse engineered from
  `KSUSBAPO64.dll`; see [`../docs/APO-DOWNMIXER.md`](../docs/APO-DOWNMIXER.md).
- No EqualizerAPO or VoiceMeeter binaries. `tools/apply_apo.ps1` attaches the
  EqualizerAPO that is already installed; the plugin path needs VoiceMeeter
  Banana's Insert Virtual ASIO driver, which ships with VoiceMeeter.
- No `work/` scratch: tones, loopback captures and registry exports stay out.
  Only the four files the acceptance test actually consumes are included.
